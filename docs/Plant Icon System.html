Icon system Shipping · flowering on

One shape,
many plants.

Every Rootly plant icon is built from a small library of base silhouettes. A specific plant is just that base wearing a skin — a set of CSS variable slots for color, variegation, and blooms. Draw ~14 shapes once; reach 50+ plants by reskinning. The recipe is pure data, so it feeds straight into the app.

01The slot system

A base is bound to named slots

Each fillable region of a silhouette points at a CSS variable instead of a baked-in hex. Override the variables and the same paths become a different plant — no new geometry, no separate file.

--leaf-1Deep / back leaves
--leaf-2Mid leaves
--leaf-3Light / front leaves
--stemStems & petioles
--veinStructural highlights
--variegationOptional marking — default transparent
--bloomOptional flower — default transparent
--pot-bodyClay pot body
--pot-rimClay pot rim

04Variegation patterns

Four marking styles, one slot

Variegation isn't one effect — it's a small named set. A recipe carries a pattern plus the --variegation color; every base ships all four overlays pre-clipped to its own leaves, so naming one is all it takes. Shown here on the trailing-vine base.

05Flowering plants — switched on

The flowers are switched on

Flowering plants now ship live. The simplest bloom is still a single Sun dot — perfect for an echeveria sending up a spike (below). For plants that carry identity in their shape, a small library of bloom-heads rides the same green bases: petals, center and accent slots, every hue pinned to the same lightness & chroma band as Sun.

06For the app

A plant icon is just data

Because a skin is only variable values, every plant becomes a tiny record. It slots into the existing Plant model as one field, and the renderer maps it to slot overrides at runtime.

// icon recipe — stored per plant
icon: {
  base:  "trailing-vine",
  palette: {
    leaf2: "#5C9A33",
  },
  variegation: {
    pattern: "speckle",
    color:   "#E7C463",
  },
  bloom: null,
}
// renderer → CSS variable slots
<div class="ic" data-veg="speckle" style="
  --leaf-2: #5C9A33;
  --variegation: #E7C463;
">
  <use href="#trailing-vine" />
</div>

One base SVG in a shared sprite, one record per plant. Flowering plants add a bloom object — a head name plus palette tokens — validated against the bloom set so no off-brand hue slips in. New cultivar = a new row, never a new drawing.

07Where this goes

14 bases → 50 plants, phased

Phase 1 · lock the system

Refine the 14 bases

  • All 14 silhouettes drawn — now tighten soil anchoring, stroke weights, optical balance
  • Lock the pot, slot palette, and clip-masked variegation as reusable rules
  • Bloom-heads + palette folded in — flowering plants switched on
  • Ship the base sprite + a starter set of ~24 skinned plants
Phase 2 · reach 50

Skin the long tail

  • Mostly recipes, not drawings — cultivars & color variants
  • Skin the flowering long tail — more heads & hues only as plants need them
  • Wire icon into the Plant model + Add-plant flow
